Title: Use Case 3 — Node Disk Pressure
Subtitle: Self-healing node filesystem capacity on Red Hat OpenShift

Divide the canvas into five clear panels:

PANEL 1 — PURPOSE AND GOAL
- Purpose: Fill a worker node filesystem past eviction thresholds so DiskPressure appears and scheduling/eviction behavior degrades.
- Goal: Detect NodeFilesystemSpaceFillingUp, diagnose disk pressure, open ServiceNow with RCA, generate remediation that frees space, clear pressure, and learn for recurrence.
- Why it matters: Disk pressure is one of the most frequent production node issues (images, logs, emptyDir, orphaned kubelet data).

PANEL 2 — HOW IT WORKS
Numbered flow with short lines:
1. Trigger writes a large file (~85% capacity) to /var/tmp on a safe worker via oc debug.
2. Kubelet sets DiskPressure; Prometheus fires NodeFilesystemSpaceFillingUp (demo for: ~1 minute).
3. Alertmanager webhooks EDA; AAP self-healing-workflow starts.
4. Diagnostics capture node conditions and filesystem context; ServiceNow incident is created.
5. Knowledge base lookup in Llama Stack.
6. AI path: OpenShift Lightspeed RAG + LLM (vLLM on Red Hat OpenShift AI) produce RCA and remediation playbook.
7. Playbook to Gitea; AAP creates Remediate Job Template.
8. Heal: remove the fill file / reclaim space; DiskPressure clears.
9. Store resolution for the learning loop.
